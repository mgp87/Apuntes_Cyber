# Comandos Linux útiles para Pentesting y Administración

> La mayoría de estos comandos son herramientas estándar de Linux. En un pentest son especialmente útiles para reconocimiento local, navegación, análisis de archivos, transferencia de ficheros, permisos, logs y automatización.

---

# 1. `whoami`

Muestra el nombre del usuario efectivo actual.

```bash
whoami
```

Ejemplo:

```text
www-data
```

Útil para saber bajo qué cuenta se está ejecutando una shell o proceso.

Comandos relacionados:

```bash
id
```

Muestra más información:

```text
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

```bash
groups
```

Muestra los grupos del usuario.

# 2. `echo`

Imprime texto o variables.

```bash
echo "Hola"
```

Variables:

```bash
echo $USER
echo $HOME
echo $PATH
echo $SHELL
```

Crear contenido:

```bash
echo "texto" > archivo.txt
```

Añadir contenido:

```bash
echo "otra línea" >> archivo.txt
```

Flags habituales:

|Flag|Función|
|---|---|
|`-n`|No añade salto de línea final|
|`-e`|Interpreta secuencias como `\n`, `\t`|
|`-E`|No interpreta secuencias especiales|

Ejemplo:

```bash
echo -e "uno\ndos\ntres"
```

# 7. `find`

Busca archivos y directorios.

Sintaxis:

```bash
find RUTA CONDICIONES
```

Buscar por nombre:

```bash
find / -name "config.php" 2>/dev/null
```

Ignorando mayúsculas:

```bash
find / -iname "*.conf" 2>/dev/null
```

Buscar archivos:

```bash
find /var -type f
```

Buscar directorios:

```bash
find / -type d -name "backup"
```

Flags y condiciones comunes:

|Parámetro|Función|
|---|---|
|`-name`|Nombre exacto/patrón|
|`-iname`|Nombre sin distinguir mayúsculas|
|`-type f`|Archivos|
|`-type d`|Directorios|
|`-size`|Tamaño|
|`-user`|Propietario|
|`-group`|Grupo|
|`-perm`|Permisos|
|`-mtime`|Modificación en días|
|`-mmin`|Modificación en minutos|
|`-maxdepth`|Limita profundidad|
|`-exec`|Ejecuta un comando sobre resultados|

Ejemplos:

```bash
find /tmp -type f
```

```bash
find . -type f -name "*.log"
```

```bash
find /var/log -type f -mtime -1
```

Archivos mayores de 100 MB:

```bash
find / -type f -size +100M 2>/dev/null
```

Archivos pertenecientes a un usuario:

```bash
find /home -user alice
```

# 8. `grep`

Busca texto mediante patrones.

```bash
grep "password" archivo.txt
```

Flags comunes:

|Flag|Función|
|---|---|
|`-i`|Ignora mayúsculas/minúsculas|
|`-r`|Busca recursivamente|
|`-R`|Recursivo siguiendo enlaces|
|`-n`|Muestra número de línea|
|`-v`|Invierte la búsqueda|
|`-E`|Expresiones regulares extendidas|
|`-w`|Coincidencia de palabra completa|
|`-l`|Muestra sólo nombres de archivos|
|`-c`|Cuenta coincidencias|
|`-A N`|N líneas después|
|`-B N`|N líneas antes|
|`-C N`|N líneas alrededor|

Ejemplos:

```bash
grep -i "error" app.log
```

```bash
grep -Rni "password" /etc 2>/dev/null
```

```bash
grep -v "^#" archivo.conf
```

Eliminar comentarios y líneas vacías:

```bash
grep -Ev '^\s*(#|$)' archivo.conf
```

Con pipes:

```bash
ps aux | grep nginx
```

# 10. `&&`

Ejecuta el segundo comando **sólo si el primero termina correctamente**.

```bash
comando1 && comando2
```

Ejemplo:

```bash
mkdir pruebas && cd pruebas
```

También existen:

```bash
comando1 ; comando2
```

Ejecuta ambos independientemente del resultado.

```bash
comando1 || comando2
```

Ejecuta el segundo sólo si el primero falla.

# 11. `>`

Redirige la salida estándar a un archivo y **sobrescribe su contenido**.

```bash

```

Ejemplo:

```bash

```

Cuidado:

```bash
> archivo.txt
```

Vacía el archivo.

# Redirecciones útiles

Linux maneja normalmente:

```text
0 = stdin
1 = stdout
2 = stderr
```

Ignorar errores:

```bash
find / -name "*.conf" 2>/dev/null
```

Guardar errores:

```bash
comando 2> errores.txt
```

Guardar stdout y stderr:

```bash
comando > salida.txt 2>&1
```

En Bash también:

```bash
comando &> salida.txt
```


Ejemplo:

```bash

```

Flags habituales:

|Flag|Función|
|---|---|

|`-i`|Clave privada|


# 23. Permisos Linux: `rwx`

Linux utiliza tres permisos fundamentales:

|Permiso|Valor|Significado|
|---|--:|---|
|`r`|**4**|Read|
|`w`|**2**|Write|
|`x`|**1**|Execute|

> El orden correcto es **`r = 4`, `w = 2`, `x = 1`**.

Los permisos se dividen en:

```text
user    group    others
 u        g        o
```

Ejemplo:

```text
rwxr-xr--
```

Separado:

```text
rwx | r-x | r--
 u     g     o
```

Conversión:

```text
rwx = 4 + 2 + 1 = 7
r-x = 4 + 0 + 1 = 5
r-- = 4 + 0 + 0 = 4
```

Resultado:

```text
754
```

## Valores frecuentes

|Valor|Permisos|
|--:|---|
|`0`|`---`|
|`1`|`--x`|
|`2`|`-w-`|
|`3`|`-wx`|
|`4`|`r--`|
|`5`|`r-x`|
|`6`|`rw-`|
|`7`|`rwx`|

Ejemplos:

```text
600 = rw------- 
644 = rw-r--r--
700 = rwx------
755 = rwxr-xr-x
777 = rwxrwxrwx
```

## Permisos en directorios

En directorios:

- `r` → listar nombres.
    
- `w` → crear/eliminar entradas.
    
- `x` → atravesar/acceder al directorio.

# 24. `chmod`

Cambia permisos.

Modo numérico:

```bash
chmod 755 script.sh
```

Modo simbólico:

```bash
chmod u+x script.sh
```

Añadir escritura al grupo:

```bash
chmod g+w archivo
```

Quitar permisos a otros:

```bash
chmod o-rwx archivo
```

Sintaxis:

```text
u = user
g = group
o = others
a = all

+ = añadir
- = quitar
= = establecer
```

Ejemplos:

```bash
chmod u+x script.sh
```

```bash
chmod go-rwx secreto.txt
```

Recursivamente:

```bash
chmod -R 755 directorio
```

# Permisos especiales

## SUID

```text
4000
```

Ejemplo:

```bash
chmod 4755 programa
```

Aparece como:

```text
-rwsr-xr-x
```

El ejecutable puede ejecutarse con el UID efectivo del propietario.

## SGID

```text
2000
```

Ejemplo:

```bash
chmod 2755 directorio
```

## Sticky Bit

```text
1000
```

Muy típico en `/tmp`:

```text
drwxrwxrwt
```

Ejemplo:

```bash
chmod 1777 directorio
```

# 31. `crontab`

Gestiona las tareas programadas de un usuario.

Ver:

```bash
crontab -l
```

Editar:

```bash
crontab -e
```

Eliminar:

```bash
crontab -r
```

Flags:

|Flag|Función|
|---|---|
|`-l`|Listar|
|`-e`|Editar|
|`-r`|Eliminar|
|`-u usuario`|Gestionar otro usuario, con permisos suficientes|

## Formato

```text
MINUTO HORA DÍA_MES MES DÍA_SEMANA COMANDO
```

Ejemplo:

```text
30 2 * * * /usr/local/bin/backup.sh
```

Significa:

```text
02:30 todos los días
```

Tabla:

|Campo|Valores|
|---|---|
|Minuto|`0-59`|
|Hora|`0-23`|
|Día del mes|`1-31`|
|Mes|`1-12`|
|Día semana|`0-7`|

Ejemplos:

Cada 5 minutos:

```text
*/5 * * * * comando
```

Cada día a las 08:00:

```text
0 8 * * * comando
```

Cada lunes:

```text
0 9 * * 1 comando
```

## Ubicaciones importantes

```text
/etc/crontab
/etc/cron.d/
/etc/cron.daily/
/etc/cron.hourly/
/etc/cron.weekly/
/etc/cron.monthly/
```

```text
    ↓

    ↓

    ↓

    ↓
ordenar por frecuencia
```

# 34. `systemctl`

`systemctl` permite **consultar, iniciar, detener, reiniciar y gestionar servicios** en sistemas que utilizan `systemd`.

Es especialmente útil para comprobar qué servicios están activos, revisar si arrancan automáticamente y diagnosticar problemas junto con `journalctl`.

---

## Ver estado de un servicio

```bash
systemctl status ssh
```

Ejemplo:

```bash
systemctl status nginx
```

La salida suele indicar:

- si el servicio está activo;
    
- PID principal;
    
- tiempo desde el arranque;
    
- últimas líneas del log;
    
- ruta de la unidad;
    
- si está habilitado al inicio.
    

---

## Iniciar un servicio

```bash
sudo systemctl start nginx
```

---

## Detener un servicio

```bash
sudo systemctl stop nginx
```

---

## Reiniciar un servicio

```bash
sudo systemctl restart nginx
```

Útil después de modificar una configuración.

---

## Recargar configuración

```bash
sudo systemctl reload nginx
```

`reload` intenta recargar la configuración **sin detener completamente el servicio**.

No todos los servicios soportan esta operación.

---

## Diferencia entre `restart` y `reload`

```text
restart
    ↓
Detiene el servicio
    ↓
Lo vuelve a iniciar
```

```text
reload
    ↓
Mantiene el servicio ejecutándose
    ↓
Recarga configuración
```

---

## Activar un servicio al arranque

```bash
sudo systemctl enable nginx
```

---

## Desactivar el arranque automático

```bash
sudo systemctl disable nginx
```

---

## Iniciar ahora y activar al arranque

Muy útil:

```bash
sudo systemctl enable --now nginx
```

Equivale aproximadamente a:

```bash
sudo systemctl enable nginx
sudo systemctl start nginx
```

---

## Desactivar y detener

```bash
sudo systemctl disable --now nginx
```

---

## Comprobar si está activo

```bash
systemctl is-active nginx
```

Salida típica:

```text
active
```

o:

```text
inactive
```

---

## Comprobar si está habilitado al arranque

```bash
systemctl is-enabled nginx
```

Posibles respuestas:

```text
enabled
disabled
static
masked
```

---

## Listar servicios activos

```bash
systemctl list-units --type=service
```

Sólo los que están ejecutándose:

```bash
systemctl list-units --type=service --state=running
```

---

## Listar todos los servicios instalados

```bash
systemctl list-unit-files --type=service
```

Esto permite ver también si están:

```text
enabled
disabled
static
masked
```

---

## Ver servicios fallidos

```bash
systemctl --failed
```

Muy útil para troubleshooting.

También:

```bash
systemctl list-units --state=failed
```

---

## Ver una unidad concreta

```bash
systemctl cat nginx
```

Muestra el fichero de definición del servicio y posibles overrides.

---

## Ver propiedades de un servicio

```bash
systemctl show nginx
```

Buscar propiedades concretas:

```bash
systemctl show nginx | grep User
```

Por ejemplo:

```bash
systemctl show nginx | grep -E 'User|Group|ExecStart'
```

---

## Ver comando de ejecución

```bash
systemctl show nginx -p ExecStart
```

---

## Ver usuario del servicio

```bash
systemctl show nginx -p User
```

---

## Ver dependencias

```bash
systemctl list-dependencies nginx
```

---

## Recargar los ficheros de configuración de `systemd`

Después de modificar o crear una unidad:

```bash
sudo systemctl daemon-reload
```

Flujo típico:

```bash
sudo nano /etc/systemd/system/mi-servicio.service
sudo systemctl daemon-reload
sudo systemctl enable --now mi-servicio
```



## Ubicaciones habituales de unidades `systemd`

```text

```

Unidades y overrides creados o modificados por el administrador.

```text

```

Habitual en distribuciones RHEL-like.

```text

```

Habitual en Debian/Ubuntu.

---

## Buscar servicios personalizados

```bash

```

```bash

```

También:

```bash

```

---

## Tipos de unidades de `systemd`

`systemctl` no gestiona únicamente servicios.

|Extensión|Función|
|---|---|
|`.service`|Servicios|
|`.socket`|Sockets|
|`.timer`|Tareas programadas|
|`.target`|Agrupaciones/estados|
|`.mount`|Montajes|
|`.automount`|Automontajes|
|`.path`|Monitorización de rutas|
|`.device`|Dispositivos|

---

## `systemd timers`

Los timers son una alternativa moderna a `cron`.

Listarlos:

```bash
systemctl list-timers
```

Todos:

```bash
systemctl list-timers --all
```

Ejemplo conceptual:

```text
backup.timer
      ↓
activa
      ↓
backup.service
```

Para investigar tareas automáticas en un sistema conviene revisar tanto:

```bash
crontab -l
```

como:

```bash
systemctl list-timers --all
```

---

## `mask` y `unmask`

`mask` impide que un servicio pueda iniciarse.

```bash
sudo systemctl mask servicio
```

Revertir:

```bash
sudo systemctl unmask servicio
```

Diferencia:

```text
disable
    ↓
No arranca automáticamente
pero puede iniciarse manualmente
```

```text
mask
    ↓
Se bloquea completamente
su inicio mediante systemd
```
