# Protocolos de red — Pentesting / Networking Cheat Sheet

> Resumen orientado a **reconocimiento, enumeración y administración autorizada**. Los ejemplos de conexión y banner grabbing deben utilizarse únicamente contra sistemas propios o incluidos en el scope.

---

# 1. Telnet

## ¿Qué es?

**Telnet** es un protocolo de acceso remoto basado en texto que permite interactuar con un servicio mediante una conexión TCP.

No proporciona cifrado.

```text
Cliente
   │
   │ TCP
   ▼
Servidor
```

Es muy utilizado actualmente para **testing de servicios TCP**, aunque el acceso remoto mediante Telnet ha sido sustituido prácticamente por SSH.

## Puerto típico

```text
TCP/23
```

## Conexión

```bash
telnet <IP> 23
```

Ejemplo:

```bash
telnet 192.0.2.10 23
```

También puede utilizarse para probar otros servicios TCP:

```bash
telnet <IP> <PUERTO>
```

Por ejemplo:

```bash
telnet 192.0.2.10 25
```

---

## Banner grabbing

Muchos servicios muestran información al conectarse:

```bash
telnet <IP> 21
```

Puede aparecer:

```text
220 FTP server ready
```

O:

```bash
telnet <IP> 25
```

```text
220 mail.example.com ESMTP
```

Esto permite identificar:

- protocolo;
    
- software;
    
- hostname;
    
- versión, si se publica;
    
- capacidades del servicio.
    

---

## Alternativa moderna: Netcat

Para comprobar simplemente si un puerto TCP responde:

```bash
nc -nv <IP> <PORT>
```

Ejemplo:

```bash
nc -nv 192.0.2.10 25
```

Esperar a recibir el banner:

```bash
nc -nv 192.0.2.10 25
```

Después se pueden introducir comandos específicos del protocolo.

---

## Uso en pentesting

Telnet puede servir para:

- comprobar conectividad TCP;
    
- identificar servicios;
    
- interactuar manualmente con protocolos de texto;
    
- realizar banner grabbing;
    
- comprender protocolos como SMTP, FTP o POP3.
    

> **Importante:** que un puerto sea accesible mediante Telnet no significa que el servicio sea Telnet. `telnet` puede utilizarse simplemente como cliente TCP.

# 2. HTTP

## ¿Qué es?

**HTTP — Hypertext Transfer Protocol** es el protocolo fundamental de la Web.

Permite la comunicación:

```text
Client
  │
  │ HTTP Request
  ▼
Web Server
  │
  │ HTTP Response
  ▼
Client
```

Se utiliza para:

- páginas web;
    
- APIs;
    
- aplicaciones web;
    
- servicios REST;
    
- microservicios;
    
- administración web;
    
- IoT y otros servicios HTTP.
    

---

## Puertos típicos

```text
TCP/80
```

HTTPS:

```text
TCP/443
```

También pueden existir aplicaciones HTTP en:

```text
8080
8000
8008
8888
3000
5000
etc.
```

No hay que asumir que HTTP sólo existe en `80`.

---

# Métodos HTTP

Los más importantes:

|Método|Uso|
|---|---|
|`GET`|Obtener recurso|
|`POST`|Enviar/crear información|
|`PUT`|Crear/reemplazar recurso|
|`PATCH`|Modificar parcialmente|
|`DELETE`|Eliminar|
|`HEAD`|Obtener headers sin body|
|`OPTIONS`|Consultar métodos/capacidades|

---

# Curl

La herramienta fundamental:

```bash
curl http://example.com
```

Mostrar headers:

```bash
curl -I http://example.com
```

Modo verbose:

```bash
curl -v http://example.com
```

Seguir redirecciones:

```bash
curl -L http://example.com
```

Mostrar headers + body:

```bash
curl -i http://example.com
```

Enviar POST:

```bash
curl -X POST http://example.com/login
```

Enviar datos:

```bash
curl -X POST -d 'user=test&password=test' http://example.com/login
```

Enviar un header:

```bash
curl -H 'Authorization: Bearer TOKEN' https://example.com/api
```

---

# HTTP Request

Ejemplo conceptual:

```http
GET / HTTP/1.1
Host: example.com
User-Agent: curl
Connection: close
```

---

# HTTP Response

```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234
```

# Banner / tecnología

```bash

```

Puede revelar:

```text

```

```text

```

```bash

```

```bash

```

# 3. FTP

## ¿Qué es?

**FTP — File Transfer Protocol** permite transferir archivos entre cliente y servidor.

Se utiliza en:

- servidores de archivos;
    
- servidores web antiguos;
    
- intercambio de ficheros;
    
- sistemas legacy;
    
- automatizaciones.
    

---

## Puertos

FTP utiliza normalmente:

```text
TCP/21
```

para el **control**.

Los datos utilizan conexiones adicionales dependiendo del modo:

```text
Active FTP
Passive FTP
```

---

# FTP Active vs Passive

## Active

```text
Client
  │
  │ TCP/21
  ▼
FTP Server

Server ─────────────► Client
       data channel
```

El servidor inicia la conexión de datos hacia el cliente.

## Passive

```text
Client
  │
  ├── TCP/21 ───────► Server
  │
  └── TCP/<data> ───► Server
```

El cliente inicia ambas conexiones.

Actualmente el modo **Passive** es muy habitual debido a firewalls/NAT.

---

# Conexión

```bash
ftp <IP>
```

Ejemplo:

```bash
ftp 192.0.2.10
```

También:

```bash
ftp <hostname>
```

---

# Banner grabbing

```bash
nc -nv <IP> 21
```

Podría devolver:

```text
220 FTP Server ready
```

Con Nmap:

```bash
nmap -sV -p21 <IP>
```

---

# Comandos FTP importantes

Una vez conectado:

```text
help
```

```text
status
```

```text
pwd
```

```text
ls
```

```text
cd <directory>
```

```text
get <file>
```

```text
put <file>
```

```text
bye
```

---

# Anonymous FTP

Algunos servidores permiten:

```text
Username:
anonymous

Password:
anonymous@example.com
```

Comprobarlo **sólo con autorización**.

Nmap:

```bash
nmap -p21 --script ftp-anon <IP>
```

# 4. SMTP

## ¿Qué es?

**SMTP — Simple Mail Transfer Protocol** se utiliza para enviar correo electrónico.

Se encuentra en:

```text
Mail Client
     │
     ▼
SMTP Server
     │
     ▼
Other Mail Server
```

---

# Puertos

|Puerto|Uso|
|--:|---|
|`25/TCP`|SMTP server-to-server|
|`587/TCP`|Message Submission|
|`465/TCP`|SMTP over implicit TLS|

---

# Banner grabbing

```bash
nc -nv <IP> 25
```

Ejemplo:

```text
220 mail.example.com ESMTP
```

También:

```bash
telnet <IP> 25
```

---

# Comandos SMTP básicos

Después de conectar:

```text
EHLO example.com
```

o:

```text
HELO example.com
```

Consultar capacidades:

```text
EHLO example.com
```

Puede devolver:

```text
250-STARTTLS
250-AUTH LOGIN
250-SIZE ...
```

Cerrar:

```text
QUIT
```

---

# SMTP Enumeration

Históricamente algunos servidores permitían consultar si un usuario existía mediante comandos como:

```text
VRFY
```

o:

```text
EXPN
```

Actualmente muchos servidores los deshabilitan.

No debe asumirse que:

```text
VRFY
```

está disponible.

---

# Nmap

```bash
nmap -sV -p25,465,587 <IP>
```

Scripts SMTP:

```bash
nmap --script smtp-commands -p25 <IP>
```

# 5. POP3

## ¿Qué es?

**POP3 — Post Office Protocol version 3** permite descargar correo electrónico desde un servidor.

Modelo típico:

```text
Mail Server
     │
     │ POP3
     ▼
Mail Client
```

Tradicionalmente está orientado a descargar mensajes al cliente.

---

# Puerto

```text
TCP/110
```

POP3 sobre TLS:

```text
TCP/995
```

---

# Conexión

```bash
telnet <IP> 110
```

o:

```bash
nc -nv <IP> 110
```

Banner típico:

```text
+OK POP3 server ready
```

---

# Comandos POP3

```text
USER username
```

```text
PASS password
```

Información del servidor:

```text
CAPA
```

Lista de mensajes:

```text
LIST
```

Obtener mensaje:

```text
RETR 1
```

Eliminar:

```text
DELE 1
```

Salir:

```text
QUIT
```

> No pruebes credenciales ni intentes acceder a buzones salvo que estén explícitamente autorizados.

---

# Nmap

```bash
nmap -sV -p110,995 <IP>
```

# 6. IMAP

## ¿Qué es?

**IMAP — Internet Message Access Protocol** permite gestionar correo almacenado en el servidor.

A diferencia del modelo tradicional de POP3:

```text
POP3
Server
  ↓
Download
  ↓
Client
```

IMAP mantiene una mayor parte del estado:

```text
Server
  │
  ├── Inbox
  ├── Sent
  ├── Drafts
  └── Folders
       │
       ▼
     Client
```

Es habitual en:

- Gmail;
    
- Microsoft 365;
    
- servidores corporativos;
    
- clientes de correo.
    

---

# Puerto

```text
TCP/143
```

IMAPS:

```text
TCP/993
```

---

# Conexión

```bash
telnet <IP> 143
```

o:

```bash
nc -nv <IP> 143
```

---

# IMAP commands

IMAP utiliza etiquetas para identificar comandos.

Ejemplo:

```text
A001 CAPABILITY
```

Respuesta:

```text
* CAPABILITY IMAP4rev1 ...
A001 OK
```

Login:

```text
A002 LOGIN username password
```

Seleccionar Inbox:

```text
A003 SELECT INBOX
```

Salir:

```text
A004 LOGOUT
```

> Evita enviar credenciales reales sobre una conexión sin TLS.

---

# Nmap

```bash
nmap -sV -p143,993 <IP>
```

# 7. Protocolos "Secure"

Un punto importante:

> **“Secure” no siempre significa un protocolo completamente diferente.**

Normalmente encontramos dos modelos:

```text
1. STARTTLS
   Conexión normal
        ↓
   Upgrade a TLS

2. Implicit TLS
   TLS desde el primer byte
```

---

# STARTTLS

Conceptualmente:

```text
TCP
 ↓
Protocol handshake
 ↓
STARTTLS
 ↓
TLS
 ↓
Encrypted communication
```

Ejemplos:

```text
SMTP 587
IMAP 143
POP3 110
```

---

# Implicit TLS

```text
TCP
 ↓
TLS
 ↓
Protocol
```

Ejemplos habituales:

```text
SMTPS 465
IMAPS 993
POP3S 995
HTTPS 443
```

---

# Comparativa

|Servicio|Sin TLS|STARTTLS habitual|TLS implícito|
|---|--:|--:|--:|
|HTTP|`80`|—|`443` HTTPS|
|FTP|`21`|`21`|`990` FTPS|
|SMTP|`25`|`25/587`|`465`|
|POP3|`110`|`110`|`995`|
|IMAP|`143`|`143`|`993`|
|SSH|—|—|`22`|

> Los puertos son convenciones habituales, no garantías. Un servicio puede ejecutarse en otro puerto.

---

# 8. HTTPS

## ¿Qué es?

HTTPS es:

```text
HTTP
+
TLS
```

Conceptualmente:

```text
HTTP
  ↓
TLS
  ↓
TCP
  ↓
IP
```

Normalmente:

```text
TCP/443
```

---

# Conexión

```bash
curl https://example.com
```

Headers:

```bash
curl -I https://example.com
```

Verbose:

```bash
curl -v https://example.com
```

---

# Certificado TLS

Puede inspeccionarse con:

```bash
openssl s_client -connect example.com:443
```

Mostrar certificado:

```bash
openssl s_client -connect example.com:443 </dev/null
```

También:

```bash
nmap -p443 --script ssl-cert <IP>
```

---

# Información interesante del certificado

Puede contener:

```text
Subject
Issuer
Validity
SAN
Public Key
Signature Algorithm
```

Los **Subject Alternative Names (SAN)** pueden revelar otros nombres DNS.

Ejemplo:

```text
example.com
www.example.com
api.example.com
```

Esto conecta con reconnaissance mediante **Certificate Transparency**.

# 12. SSH

## ¿Qué es?

**SSH — Secure Shell** es el estándar habitual para administración remota segura.

Permite:

- terminal remota;
    
- ejecución de comandos;
    
- transferencia de archivos;
    
- tunneling;
    
- port forwarding;
    
- autenticación mediante claves.
    

---

# Puerto

```text
TCP/22
```

---

# Conexión

```bash
ssh user@host
```

Ejemplo:

```bash
ssh alice@192.0.2.10
```

Puerto personalizado:

```bash
ssh -p 2222 alice@192.0.2.10
```

---

# Ejecutar comando remotamente

```bash
ssh user@host 'whoami'
```

Por ejemplo:

```bash
ssh user@192.0.2.10 'hostname'
```

Esto ejecuta el comando en el servidor remoto.

---

# SSH keys

Generar una clave:

```bash
ssh-keygen
```

Ed25519:

```bash
ssh-keygen -t ed25519
```

Archivos habituales:

```text
~/.ssh/id_ed25519
~/.ssh/id_ed25519.pub
```

La clave:

```text
id_ed25519
```

es privada.

La clave:

```text
id_ed25519.pub
```

es pública.

---

# Copiar clave pública

Con:

```bash
ssh-copy-id user@host
```

Después:

```bash
ssh user@host
```

puede utilizar autenticación mediante clave.

---

# SSH verbose

Muy útil para troubleshooting:

```bash
ssh -v user@host
```

Más detalle:

```bash
ssh -vv user@host
```

Máximo:

```bash
ssh -vvv user@host
```

Permite observar:

- negociación;
    
- métodos de autenticación;
    
- claves;
    
- errores;
    
- algoritmos negociados.
    

---

# Banner SSH

```bash
nc -nv <IP> 22
```

Puede aparecer algo como:

```text
SSH-2.0-OpenSSH_9.x
```

También:

```bash
nmap -sV -p22 <IP>
```

# 13. SCP

## ¿Qué es?

**SCP — Secure Copy Protocol** permite copiar archivos utilizando SSH.

```text
Local
  │
  │ SSH
  ▼
Remote
```

---

# Subir archivo

```bash
scp file.txt user@host:/tmp/
```

Ejemplo:

```bash
scp report.pdf alice@192.0.2.10:/home/alice/
```

---

# Descargar archivo

```bash
scp user@host:/path/file.txt .
```

---

# Copiar directorio

```bash
scp -r directory/ user@host:/tmp/
```

---

# Puerto personalizado

```bash
scp -P 2222 file.txt user@host:/tmp/
```

> En `scp` el puerto se especifica con `-P` mayúscula.

---

# 14. SFTP

## ¿Qué es?

**SFTP — SSH File Transfer Protocol** es un protocolo de transferencia de archivos que funciona sobre SSH.

No es:

```text
FTP + TLS
```

Es un protocolo diferente.

```text
SFTP
  ↓
SSH
  ↓
TCP/22
```

---

# Conexión

```bash
sftp user@host
```

Puerto personalizado:

```bash
sftp -P 2222 user@host
```

---

# Comandos SFTP

```text
ls
```

Lista remoto.

```text
pwd
```

Directorio remoto.

```text
lpwd
```

Directorio local.

```text
cd <dir>
```

Cambiar directorio remoto.

```text
lcd <dir>
```

Cambiar directorio local.

Descargar:

```text
get file.txt
```

Subir:

```text
put file.txt
```

Descargar directorio:

```text
get -r directory/
```

Subir directorio:

```text
put -r directory/
```

Salir:

```text
exit
```

---

# SCP vs SFTP

|Característica|SCP|SFTP|
|---|---|---|
|Basado en SSH|✅|✅|
|Puerto típico|`22`|`22`|
|Transferencia|✅|✅|
|Interactivo|❌|✅|
|Listar directorios|Limitado|✅|
|Gestión de archivos|Limitada|✅|
|Uso moderno|Transferencias rápidas|Gestión interactiva|

Para nuevas automatizaciones, **SFTP suele ofrecer más funcionalidades**.

---

# 15. FTPS vs SFTP

No confundir:

```text
FTPS
=
FTP + TLS
```

mientras:

```text
SFTP
=
SSH File Transfer Protocol
```

Son protocolos completamente diferentes.

||FTPS|SFTP|
|---|---|---|
|Base|FTP|SSH|
|Cifrado|TLS|SSH|
|Puerto típico|`990` implícito / `21` explícito|`22`|
|Canales FTP|Sí|No|
|SSH|❌|✅|

# 16. Banner grabbing — resumen

Una de las primeras técnicas de enumeración consiste en conectar al servicio y observar qué información publica.

## Netcat

```bash
nc -nv <IP> <PORT>
```

Ejemplos:

```bash
nc -nv <IP> 21
```

```bash
nc -nv <IP> 22
```

```bash
nc -nv <IP> 25
```

```bash
nc -nv <IP> 110
```

```bash
nc -nv <IP> 143
```

---

# Nmap

Para detectar servicio y versión:

```bash
nmap -sV -p22,21,25,80,110,143,443 <IP>
```

`-sV` intenta identificar:

```text
Service
Product
Version
```

Ejemplo conceptual:

```text
22/tcp   open  ssh     OpenSSH
25/tcp   open  smtp    Postfix
80/tcp   open  http    Apache
```

---

# Banner grabbing HTTPS

```bash
openssl s_client -connect <IP>:443
```

Con hostname/SNI:

```bash
openssl s_client -connect example.com:443 -servername example.com
```

Esto es importante porque un servidor puede alojar múltiples dominios:

```text
             IP
              │
       ┌──────┴──────┐
       │             │
 example.com     api.example.com
       │             │
       └─── HTTPS ───┘
```

El **SNI** permite indicar qué hostname se está solicitando durante la negociación TLS.

  ↓

      ↓
SMTP
      ↓

      ↓

      ↓

      ↓

      ↓

# 20. Comandos que conviene memorizar

# 21. Lo más importante para pentesting

No memorices solamente:

```text
21 = FTP
22 = SSH
25 = SMTP
80 = HTTP
110 = POP3
143 = IMAP
443 = HTTPS
```

Memoriza la relación:

```text
PORT
 ↓
PROTOCOL
 ↓
SERVICE
 ↓
COMMANDS
 ↓
CAPABILITIES
 ↓
ATTACK SURFACE
```

Por ejemplo:

```text
143
 ↓
IMAP
 ↓
CAPABILITY
 ↓
STARTTLS
 ↓
AUTH methods
 ↓
Mailboxes
 ↓
Configuration / authentication
```

Ese proceso de **enumeración sistemática** es mucho más importante que memorizar una lista de puertos.
